# Telegram-боты для учебной группы (МТУСИ)

Один процесс (`bot.py`, systemd-сервис) для одного чата учебной группы. Общий
бот-аккаунт, общий `.env`, один логин в МТУСИ. Внутри — три задачи:

| задача | что делает | когда |
|---|---|---|
| **посещаемость** | самоотметка на парах: в момент начала пары постит в топик предмета список студентов кнопками; студент нажимает своё имя (личность сверяется со списком контактов группы через userbot-сессию); в конце пары — итог присутствовал/отсутствовал. Плюс **панель для админа** (`/links` в личке) для ссылок на конференции по предметам | постоянно (long-poll) |
| **дайджест расписания** (`telegram_post.py`) | логинится в lk.mtuci.ru, парсит пары на сегодня и постит их одним **закреплённым сообщением-таблицей** (Время / Предмет / Преподаватель / Аудитория) в чат объявлений; открепляет вчерашнее; в дни без пар молчит | раз в день, ~08:00 МСК |
| **ссылки на конференции** (`lms_scraper.py`) | логинится в lms.mtuci.ru (Moodle) через SSO **по SOCKS-прокси с российским выходом** (иначе капча), достаёт из каждого курса ссылку Контур.Толк / BBB и закрепляет её (кнопкой **▶️ Подключиться**) в топике предмета; перепощивает только при изменении | раз в день, ~07:35 МСК |

Обе ежедневные задачи запускает главный цикл `bot.py` (отдельными процессами,
чтобы не блокировать бота) — cron не нужен.

## Установка

```bash
git clone https://github.com/stxlvn/mtusi-telegram-bots.git
cd mtusi-telegram-bots
python -m venv venv && ./venv/bin/pip install -r requirements.txt
./venv/bin/playwright install --with-deps chromium

cp .env.example .env      # заполни: логин/пароль МТУСИ, токен бота, chat_id, owner_id
```

Вся конфигурация — через переменные окружения, см. [`.env.example`](.env.example).
`.env` и весь каталог `data/` (ростер, cookie, состояние — реальные персональные данные)
в `.gitignore`. Userbot-сессия для сверки личности и cookie LMS настраивается отдельно —
см. [`userbot/README.md`](userbot/README.md).

## Запуск

Один systemd-сервис:

```ini
[Service]
ExecStart=/path/mtusi-telegram-bots/venv/bin/python /path/mtusi-telegram-bots/bot.py
WorkingDirectory=/path/mtusi-telegram-bots
Restart=always
```

Время ежедневных задач — константы `SCHEDULE_POST_AT` / `LMS_SCRAPE_AT` в `bot.py`.
`telegram_post.py` и `lms_scraper.py` можно и запустить руками (`./venv/bin/python
telegram_post.py`) — они самостоятельные.

### Капча на lms.mtuci.ru

Moodle закрыт анти-бот щитом, который выдаёт слайдер-капчу **всем не-российским IP**.
С российского IP капчи нет вообще. Поэтому `lms_scraper.py` ходит в LMS **через
SOCKS-прокси с российским выходом** (`LMS_PROXY` в `.env`) — а дальше просто логинится
по тому же Keycloak МТУСИ (`MTUCI_EMAIL` / `MTUCI_PASSWORD`, что и парсер расписания)
и читает список курсов. Ни браузера, ни cookie-файлов.

Как поднять российский выход:

1. Возьми любой дешёвый VPS у российского провайдера (нужен свой выделенный IP).
2. Прокинь с него SOCKS5 на машину бота, например через `autossh`:
   ```ini
   # /etc/systemd/system/lms-proxy.service
   [Service]
   Environment=AUTOSSH_GATETIME=0
   ExecStart=/usr/bin/autossh -M 0 -N -D 127.0.0.1:1081 \
     -o ServerAliveInterval=30 -o ExitOnForwardFailure=yes root@<RU-VPS-IP>
   Restart=always
   ```
3. `LMS_PROXY=socks5h://127.0.0.1:1081` в `.env`.

Если прокси отвалится, LMS вернёт капчу — бот один раз напишет в личку
(`systemctl status lms-proxy`). Ссылки при этом остаются те, что уже нашли; можно
задать вручную через `/links`.
